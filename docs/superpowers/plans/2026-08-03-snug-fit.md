# Snug Fit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the delivered Tin Melody app into Snug Fit — a grid packing puzzle with 200+ solver-verified levels across 8 chapters.

**Architecture:** A deterministic cell-grid model (containers with blocked cells, polyomino items, declarative constraints) drives everything. Levels are built and *proved solvable* by an offline Swift CLI that ships `Levels.json`; the app only reads and plays them. UI is SwiftUI + Canvas, reusing the adaptive-layout approach already proven in this project.

**Tech Stack:** Swift 5, SwiftUI (iOS 15.6), Canvas/Path drawing, Core Graphics generators compiled with `swiftc`, UserDefaults JSON persistence.

## Global Constraints
- iOS 15.6+; `NavigationView` only (no `NavigationStack`); no iOS 16+ APIs.
- Custom Path/Canvas glyphs only — no SF Symbols, no emoji, English (US) only.
- Forced Light appearance; theme-independent palette.
- MARKETING_VERSION 1.0, CURRENT_PROJECT_VERSION 1 in **both** Debug and Release — never bump.
- `TARGETED_DEVICE_FAMILY = "1,2"`; `~ipad` keeps all four orientations (ITMS-90474).
- Offline only: no network, no WebView, no notifications, no permissions. The WebView gate stays deleted.
- Bundle id `com.snugfit.app`; app name "Snug Fit" (contains a space).
- Installed size ≥ 18 MB, < 99 MB.
- Work in `development/Snug Fit`; deliver by `mv` to `for_human_review_apps/`.
- Verification is non-interactive: `xcodebuild` clean + `xcrun simctl` screenshots with the pixel-verified capture helper. Temporary `SNUG_*` env hooks are allowed during verification and MUST be removed before delivery.

### Task 2: Level model + generator/solver CLI (the heart)

**Files:**
- Create: `art_src/levelgen.swift`
- Create (output): `Snug Fit/Levels/Levels.json`

**Interfaces:**
- Produces JSON decoded by Task 3's `SnugLevel`:

```json
{"levels":[{"id":"c1_01","chapter":1,"container":{"name":"Carry-On","w":6,"h":8,"blocked":[[0,0]],"art":"cont_carryon"},
"items":[{"id":"i0","name":"Rolled Shirt","cells":[[0,0],[1,0]],"rotatable":true,"weight":2,"tags":["soft"],"art":"item_shirt"}],
"constraints":[{"kind":"weightLimit","value":40}],
"solution":[{"item":"i0","x":1,"y":2,"rot":0}],
"par":7,"stars":[7,10,14],"difficulty":38}]}
```

- Constraint kinds (exact strings): `weightLimit`, `balance`, `fragileOnTop`, `heavyLow`, `keepApart`, `keepTogether`, `uprightOnly`, `reachable`.

- [ ] **Step 1: Write the invariant test as an assertion pass in the CLI**

The CLI is its own test harness. It must `fatalError` on any violated invariant so a bad level can never be written:

```swift
func assertLevelValid(_ lvl: Level) {
    precondition(!lvl.items.isEmpty, "\(lvl.id): no items")
    precondition(Set(lvl.items.map(\.id)).count == lvl.items.count, "\(lvl.id): duplicate item ids")
    precondition(lvl.solution.count == lvl.items.count, "\(lvl.id): solution does not cover every item")
    precondition(placementIsLegal(lvl, lvl.solution), "\(lvl.id): stored solution is illegal")
    precondition(solve(lvl) != nil, "\(lvl.id): independent solver found no solution")
    precondition(lvl.par >= lvl.items.count, "\(lvl.id): par below item count")
}
```

- [ ] **Step 2: Implement the model, constructor, solver**

`Grid` (w, h, blocked set), `Item` (cells, rotations precomputed by rotating 90°, weight, tags), `Constraint` enum, `Placement` (item id, x, y, rot).

Construction: shuffle a seeded RNG, place items by backtracking until fill density ≥ target; the resulting placement is the stored solution.
Derivation: mark `fragile` only for items with no occupied cell directly above in that solution; `heavy` only for items whose solution cells are all in the bottom third; `keepApart` pairs chosen from items that are non-adjacent in the solution; `keepTogether` from a connected subset.
Solver: independent backtracking over items sorted by cell count descending, pruning on constraint violation; counts solutions up to a cap of 200.
Difficulty score: `items*4 + constraints*8 + density*40 - log2(solutionCount)*6`, clamped 0…100; chapter = bucketed by score.

- [ ] **Step 1: Write the engine test as a DEBUG self-check**

`SnugBoard.selfTest()` runs at first use in DEBUG over the first 20 shipped levels: applying each level's stored solution through `place(...)` must return `.ok` every time and end with `isSolved == true`.

```swift
#if DEBUG
static func selfTest() {
    for lvl in SnugLevelBook.all.prefix(20) {
        let b = SnugBoard(level: lvl)
        for p in lvl.solution {
            precondition(b.place(itemID: p.item, at: (p.x, p.y), rot: p.rot) == .ok,
                         "\(lvl.id): stored solution rejected at \(p.item)")
        }
        precondition(b.isSolved, "\(lvl.id): stored solution did not solve the board")
    }
}
#endif
```

- [ ] **Step 2: Implement the engine**

Occupancy grid, legality = inside bounds + not blocked + no overlap + all constraints satisfied for the *complete* board (partial boards only check the local rules: bounds, overlap, uprightOnly, heavyLow, reachable). `violations` returns the English reasons used by the refuse toast.

- [ ] **Step 3: Implement BoardView**

Canvas draws the container grid, blocked cells hatched, placed items as their art clipped to their cells, and a drag ghost snapped to the nearest cell with a green/amber tint for legal/illegal. Tray is a horizontal scroll of remaining items. Buttons: back, undo, rotate, hint. Rule chips above the board. Win sheet: stars earned, moves vs par, "Next level".
